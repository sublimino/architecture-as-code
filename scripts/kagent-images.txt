# Images the upstream kagent 0.9.9 charts reference. Consumed by
# scripts/kagent-infra.sh, which docker-pulls each one on the host and then
# hands the set to scripts/kind-load-verified.sh — the same pull-to-host then
# prove-on-node pattern scripts/foundation-images.txt uses, and for the same
# reason: `kind load` can exit 0 having transferred nothing.
#
# ─── Why these are preloaded rather than left to the mirror ────────────────
#
# scripts/registry-cache.sh mirrors exactly five hosts: docker.io,
# registry.k8s.io, ghcr.io, quay.io and mirror.gcr.io. cr.kagent.dev is not
# among them and there is no hosts.toml for it on the node, so the three
# cr.kagent.dev images below would be pulled straight from the internet by
# every kubelet on every cold cluster, with no cache and no verification that
# they arrived. Preloading them makes the install deterministic; the ghcr.io
# and docker.io entries are preloaded alongside them so one list covers the
# whole control plane rather than two mechanisms covering half each.
#
# Lines are `REFERENCE` or `REFERENCE  # comment`. Blank lines and comments are
# skipped. The OBSERVABILITY marker below splits the file: everything above it
# is always loaded, everything below it only when ENABLE_OBSERVABILITY=true.

cr.kagent.dev/kagent-dev/kagent/controller:0.9.9
cr.kagent.dev/kagent-dev/kagent/ui:0.9.9
ghcr.io/kagent-dev/kagent/tools:0.2.1
docker.io/library/postgres:18.3-alpine

# ghcr.io/kagent-dev/kmcp/controller:0.3.0 is deliberately absent. kmcp is
# disabled — see the KMCP section of d2-signalloom/infra/kagent/values.yaml for
# the two proven schema incompatibilities that block it. Re-add this line in
# the same change that flips kmcp.enabled back to true; the
# "every always-on image in the list appears in the base render" test in
# d2-signalloom/test/kagent-chart.bats keeps the two in step in both directions.

# ─── The two agent RUNTIME images, neither of which any chart template names ─
#
# The controller materialises each Agent CR into its own Deployment and picks
# the runtime image itself, so both are invisible to `helm template`. Omitting
# them makes the install look complete and every reconciled agent sit in
# ImagePullBackOff. Which of the two is used depends on the Agent CR:
#
#   runtime: go      golang-adk   <- all eight of Signal Loom's agents
#   runtime: python  app          <- the chart's own observability/promql agents
#
# Both are on ghcr.io rather than cr.kagent.dev because
# d2-signalloom/infra/kagent/values.yaml sets
# `controller.agentImage.registry: ghcr.io` — cr.kagent.dev does not carry
# golang-adk at all. See that file for the full reasoning; if you change the
# registry there, change these two lines in the same commit.
#
# The controller references golang-adk by DIGEST, not by tag. Preloading the
# tag still helps — it puts the blobs on the node — but the digest reference is
# what kubelet resolves, and ghcr.io IS one of the five hosts
# scripts/registry-cache.sh mirrors, so the digest resolves through the
# pull-through cache rather than the open internet. That is the difference from
# cr.kagent.dev, which has no mirror and no cache.
ghcr.io/kagent-dev/kagent/golang-adk:0.9.9
ghcr.io/kagent-dev/kagent/app:0.9.9
