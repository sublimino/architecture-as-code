## 1. What was actually broken

P1-1 produced a correct schema and connected it to the two language artefacts with
`scripts/sync_coding_agent_schema.py`, which greps the Go source for the literal
`` `json:"pid"` `` and the Python source for `"view_file"`. That is a presence probe. It is
satisfiable by a comment, it cannot see a field present in code but absent from the schema, and it
never parses either language.

Measured on the integration tip (`9f1281e1`) before any code was written for this card:

| Payload | Go `UnmarshalJSON` | Python `from_dict` |
|---|---|---|
| top-level `prompt_text: "…"` | rejected | **ACCEPTED**, silently dropped |
| `process.cmdline: "--api-key sk-ant-…"` | **ACCEPTED**, silently dropped | **ACCEPTED**, silently dropped |
| `metrics.tool_counts.<unlisted>` | **ACCEPTED** | ACCEPTED (folded to `other_count`) |
| `network` absent | rejected | rejected (`KeyError`) |

`python3 -c 'import jsonschema'` raises `ModuleNotFoundError` on the target hosts, so the schema's
`additionalProperties: false` was enforced by **no executing code anywhere in the repository**.

The allow-list on which the Zero-Customer-Payload invariant rests was, at the wire boundary, a
document. A producer placing a credential in an unlisted nested field was accepted by both
consumers.

**What replaced the presence probe.** `sync_coding_agent_schema.py` is kept — it still passes and
still guards P1-1's hand-written models, which remain in use at collection time. It is no longer
the *only* link. The generator is.

## 2. The enforcement points

"Frozen" is not a property of the schema. It is the property of a set of agents that can fail.
There are exactly four ways the shape and the code can come apart, and each has its own agent:

| Departure | Agent | Falsified by |
|---|---|---|
| A sender emits a shape outside the contract | closed-world decoders, both languages | mutation: deleting the unlisted-key check kills **9 subtests on each side, symmetrically** |
| One consumer accepts what the other rejects | **457-case differential corpus** + 38-case rejection corpus, both read by both suites | see §2.1 — five real asymmetries found, all fixed |
| An artefact stops matching the schema | `--check` regenerate-and-diff | appending one comment to `wire_gen.go` → `DRIFT: … does not match a fresh generation`, exit 1 |
| The schema changes and artefacts do not | SHA-256 embedded in both artefacts | one-byte schema edit → `schema digest drift: wire_gen.go records 2000426d… but … hashes to <new>` |

### 2.1 What the hand-written corpus could not have caught

`fixtures/reject/MANIFEST.json` is 38 cases someone thought of. **Every real asymmetry found on
this card was one nobody thought of, and none had a manifest case.** A reject-list encodes
predictions; it cannot cover a disagreement not predicted.

So `fixtures/differential/CORPUS.json` (**457 cases**, generated by
`scripts/build_differential_corpus.py`) enumerates *every* field against *every* adversarial value
class — anchor behaviour, type confusion, null, numeric form, unicode class, case-variant key
spellings, and eleven whole-document probes. Each case carries the **complete payload text** and
its **expected verdict**; both suites decode identical bytes and assert `actual == expected` —
deliberately **not** `go_verdict == py_verdict`, because two decoders agreeing to accept something
they should refuse is a shared defect, not agreement.

Five asymmetries it and the review pass found, all closed:

| # | Input | Go before | Python before |
|---|---|---|---|
| 1 | `process.comm = "claude\n"` | reject | **ACCEPT** — Python's `$` matches before a final newline; `re.match` compounds it. Fired on all 12 patterned fields. Fixed with `re.fullmatch` |
| 2 | `process.rss_bytes = "5"` | **ACCEPT** as `5` — `json.Number` takes a quoted number | reject. Fixed with a leading-quote guard; hit all 20 integer fields |
| 3 | `tenant_id = null` | **ACCEPT** as `""` — `encoding/json` treats null as a no-op | reject. Fixed with an explicit null check |
| 4 | multi-byte string at a length bound | byte count | codepoint count. Fixed with `utf8.RuneCountInString` |
| 5 | `{"x": NaN}` | reject as invalid JSON | **ACCEPT** — `json.loads` admits `NaN`/`Infinity` by default. Fixed with `parse_constant` |

Items 1, 3 and 5 are latent in v1 only by accident — `harness` is saved by its enum, optional
strings by patterns that refuse empty. Accident is not a control, and the version policy explicitly
permits adding a field that would remove the accident.

**A sixth was found in the test harness rather than the code, and is the sharpest of the six.** The
corpus's first run reported 46 Go "mismatches" that were not decoder defects at all: the Python side
passed a parsed dict to `decode_wire` while the Go side unmarshalled into `any` and re-marshalled,
which renders `float64(1.0)` as `1`. **The two languages were being handed different bytes for the
same case** — the exact blind spot this card exists to remove, wearing a test harness as a disguise.
The corpus now carries payload *text*, so neither side can construct the input differently from the
other.

## 3. Payload shape

Exactly P1-1's allow-list. **41 field paths**, neither added to nor removed from. Both languages
derive the identical list from the schema and assert its size is 41; a field added at freeze time
fails both suites.

```
schema_version harness session_id timestamp observed_at tenant_id agent_id host_id
process{pid ppid comm rss_bytes cpu_ticks}
kanban{task_id shortcode role elapsed_s}
metrics{step_count tokens_in tokens_out tool_counts{…14 fixed keys…}}
network{inference_endpoint egress_bytes}
```

`additionalProperties: false` holds at **every** level, and is now enforced at every level by
generated code rather than asserted by an uninstalled validator.

### 3.1 The free-text budget this mission opened

Before SLCD the widest field that could reach a persisted record was a **bounded integer or a
closed five-member enum** — `BoundedProcessAttributes` (`models.py:58`) exports `health_state`
(`HealthState`: `starting|running|stopped|failed|unknown`), `cpu_time_ms`,
`resident_memory_bytes`, `exit_code`, `restart_count`, gated by `ALLOWLISTED_PROCESS_ATTRIBUTES`
(`filter.py:66`). Zero free-text fields.

> The SLCD card's "Verified facts" cites `filter.py:34-48` for this; lines 34-48 of that file are
> an import block. The allow-list is at `filter.py:66` and the type is `models.py:58`. Recorded so
> the next card does not inherit the wrong citation.

`codingagent.v1` converts that numeric-and-enum surface into a string-carrying one. The honest
number:

**616 bytes of caller-influenceable string per record**, across 13 fields
(`schema_version` is a 5-byte `const`; the other 12 are length- *and* pattern-bounded).

Pinned by `test_total_string_budget_is_bounded_and_known`. A later widening fails on a number
rather than slipping past prose nobody re-reads.

**The widest single channel is `network.inference_endpoint`: 128 bytes of `^[a-zA-Z0-9.-]{1,128}$`.**
That is ample to carry a 64-byte secret shaped as a hostname. The bound is P1-1's and this card may
not narrow it — naming it explicitly, with a test that fails if it stops being the widest, is what
this card can do. **P1-GOV inherits this knowingly, not silently.**

### 3.2 `comm` is not the harness

P1-PRE F1: `/proc/<pid>/comm` is 15-byte truncated, Antigravity's binary is `agy`, and Codex runs
as `node`. The `antigravity-agy.json` fixture carries `harness: "antigravity"` with `comm: "agy"`
precisely so the frozen contract is exercised by a record where the two disagree. Both suites
assert it.

### 3.3 `tool_counts` leniency: two boundaries, two rules

P1-1 deliberately folds unknown MCP tool names into `other_count` so a customer tool name cannot
expand the schema. That is correct **at collection**. At the **wire** boundary an unlisted key is
rejected, because the sender is already supposed to have normalised. `ToolCounts.from_dict` keeps
folding; `decode_wire` / `DecodeWire` reject. P1-1's behaviour is not gutted.

## 4. Transport

`POST /api/v1/telemetry/coding-agents`, `Content-Type: application/json`.

| Header | Required | Note |
|---|---|---|
| `Content-Type: application/json` | yes | pinned as `const` in the OpenAPI |
| `X-SignalLoom-Contract: codingagent.v1` | yes | **structural** version. A consumer branches on this value, never on payload shape |
| `Authorization: Bearer …` | yes | verified by `ProtectedRouter.authorize` |
| `X-SignalLoom-Tenant` | **no — reserved, NOT trusted** | see below |

### 4.1 Canonical encoding

UTF-8 · keys sorted lexicographically at every level · no insignificant whitespace · no HTML
escaping · no trailing newline.

Neither standard library does this by default: Go's `encoding/json` escapes `<`, `>`, `&`; Python's
`json.dumps` escapes non-ASCII and does not sort unless asked. Both sides are configured
explicitly rather than relied upon to agree. Verified byte-for-byte:

| Fixture | Canonical SHA-256 | Bytes |
|---|---|---|
| `claude.json` | `0848c05c8c4e4c8923e5c97c89e34f0f725d6a9ae00fcbbbd5cdf40f85d419c9` | 872 |
| `antigravity-agy.json` | `f6d1464dffeaed2c39a78386079a4cba7235c8084b17f673a56e9b9797433f0b` | 769 |

Both languages compare against **these recorded constants** in `fixtures/canonical-digests.json`,
so a unilateral encoder change on either side fails its own suite. Python-encoded bytes are
committed under `fixtures/canonical/` and decoded and re-encoded by the Go suite; Go-encoded bytes
are committed under `fixtures/go-encoded/` and decoded and re-encoded by the Python suite.

**Stated precisely, because the weaker version reads stronger than it is:** the two committed
directories are byte-identical (that is the property under test), and the digest table was first
produced by the Python encoder. So the table is not an *independently derived* oracle — it is a
tripwire. What it catches is any subsequent change on either side; what it cannot catch is a
founding error made identically by both encoders at freeze time. The genuine cross-check is the
re-encode assertion: each language must reproduce the *other's* committed bytes exactly.

### 4.2 Tenant context

`X-SignalLoom-Tenant` is declared in v1 and **the server does not read it**. Tenancy is derived
from the verified principal by `ProtectedRouter.authorize` and copied by
`TenantClaimFromRequestContext` (`signal-ingest/api/tenant_bridge.go`), which consults no header,
query parameter, path value or body field. A client-supplied value influences nothing.

It is reserved now, before SLCD-P2-2's enforcement lands, so that a consumer written against v1
today needs no rewrite later. Adding it after the fact would have been a header addition to a
frozen contract.

### 4.3 Rejection responses

| Status | Meaning |
|---|---|
| `202` | accepted for ingestion |
| `400` | departs from the frozen contract — unlisted field at any depth, missing required field, duplicate key, bound or pattern violation |
| `401` / `403` | no verified principal / not authorised for this tenancy |
| `422` | Zero-Customer-Payload pre-export gate refused the record |

The `422` body is **P1-2's `DetectionReport`, exactly**: `detected`, `provider_counts` (all nine
`CredentialProvider` members), `fingerprints`, `reasons`. The generator **parses
`payload_validator.py` with `ast`** rather than restating the shape, and the Python suite
cross-checks the frozen document against the live `CredentialProvider` enum and
`DetectionReport().to_dict()`. A hand-copy would drift the moment P1-2 adds a provider.

Because a rejection body is itself an export surface, its strings are bounded here even though
P1-2 does not bound them in memory: fingerprints are exactly 64 hex characters (`maxItems` 256),
reasons are ≤128 characters of `^[a-z0-9_()=. ]$` (`maxItems` 64). Neither carries a fragment of
matched text.

**Why P1-2's shape is a response and not a request field.** The card requires both that the frozen
contract not exceed P1-1's allow-list and that it carry P1-2's fingerprint shape exactly. Those
reconcile only if `DetectionReport` is not a payload contributor — and it is not:
`payload_validator.py` is a *pre-export gate*, not a collector. So the request envelope stays
byte-identical to P1-1's allow-list and the detection shape is frozen as the rejection body.

## 5. ROUTING GAP — open, owned by SLCD-P5-1

**`/api/v1/telemetry/coding-agents` does not reach signal-ingest today.**

`d2-signalloom/apps/dashboard-signalloom/nginx.conf:102-104`:

```nginx
location /api/ {
  set $api http://fe-signalloom-api.fe-signalloom.svc.cluster.local:8000;
  proxy_pass $api$request_uri;
```

**The path is not unrouted — it is routed to the wrong backend.** `/api/` is proxied, to
`fe-signalloom-api`, which is a different service from signal-ingest. A request to the frozen path
crosses the wire, reaches FastAPI, and 404s *there*.

That distinction changes the fix and the diagnosis:

- **The 404 is FastAPI's, not nginx's.** A genuinely unproxied POST hits the SPA catch-all
  (`nginx.conf:341`, `try_files … /index.html`) and nginx answers **405**. So "did the request
  cross the wire" does *not* disambiguate a missing route here.
- **"Add an nginx route" is not sufficient on its own.** Either signal-ingest gains a route
  reachable under the existing `/api/` proxy, or a new proxy prefix is added — and the dashboard
  client's auto-`/api` prefix (`src/api/client.ts:241`) has to be accounted for either way.

No route for this path is registered anywhere in signal-ingest today. Asserted, not assumed:
`TestCodingAgentWireContract_RoutingGapIsStillOpen` pins `location /api/` to line 102, pins its
upstream to `fe-signalloom-api`, and greps `api/auth.go` and `api/handlers.go` for the frozen path.
**That test fails when SLCD-P5-1 closes the gap** — at which point it and this section are updated
together, rather than this document quietly going stale.

**Diff against the current surface:** the OpenAPI document declares one path, one verb, and one new
request schema. Every one of them is new. There is no coding-agent-telemetry route in the codebase
to diff against.

## 6. Version policy

`codingagent.v1` is immutable except for **optional property additions**, which leave `required`
unchanged. Everything else takes `codingagent.v2`.

Decided by code, not judgement: `gen_wire_contract.py --classify OLD NEW` returns a verdict and
reasons, exits 0 for compatible and 2 for incompatible, and an incompatible verdict **names the
label the change requires**.

| Change | Verdict |
|---|---|
| add an optional property | `compatible` |
| drop a property from `required` | `compatible` |
| add a required property | `incompatible` |
| make an existing property required | `incompatible` |
| remove any property | `incompatible` |
| narrow a bound | `incompatible` |
| **widen** a bound | `incompatible` |
| add or remove an enum member | `incompatible` |

Widening is incompatible on purpose. It reads like a relaxation, but a v1 consumer still refuses a
value the widened producer now considers legal, so producer and consumer disagree about validity.
That is a break.

### 6.1 What "forward compatible" actually means here

Closed-world decoding and "new fields never break old consumers" are in **direct opposition** — a
decoder that rejects unlisted keys rejects a new field by construction. The honest, testable
property is:

> An optional addition to v1 leaves every previously-valid payload valid and leaves `required`
> unchanged, so a decoder **regenerated** from the extended schema still accepts the original v1
> fixture.

`test_a_v1_decoder_regenerated_with_an_optional_field_still_decodes_v1` proves all three halves: the
regenerated decoder accepts the original fixture, accepts the fixture carrying the new optional
field, and **the un-regenerated decoder still refuses it** — which is why an addition requires a
regeneration rather than being silently tolerated.
