Signal Loom provides end-to-end governance, kernel-level confinement, and cryptographic attribution for external AI agents running as standard Linux processes outside Kubernetes (such as design-partner workloads from AgentMaxxing Inc.).

This guide details the complete operational lifecycle: registering an agent with an attributable human operator, enrolling the external host via one-time credential exchange, running under Linux Landlock LSM confinement and nono supervision, enforcing descriptor-relative artifact verification, and observing verified evidence states in the Signal Loom Dossier.

## Architecture & Verified Evidence Flow

The external agent integration bridges Linux kernel security controls with Signal Loom's centralized governance plane. All observable actions generate privacy-preserving, hash-chained telemetry without ever exfiltrating raw user data or model payloads.

## Non-Negotiable Privacy & Confinement Boundaries

Signal Loom's external agent integration enforces strict security and privacy boundaries at every layer:

1. **Zero Raw Data Ingestion (Metadata Only)**:
   - Prohibited fields—including `payload`, `raw_payload`, `memory_dump`, raw terminal streams, and file byte contents—are stripped by storage boundary sanitizers before database insertion (`Migration 042`).
   - Signal Loom records only observable telemetry: process health, CPU percentage, RSS memory bytes, exit codes, file metadata (root, size, mtime, SHA-256 digest), and egress socket destinations.
2. **Descriptor-Relative Filesystem Confinement (`openat2`)**:
   - The agent process operates under Linux Landlock LSM (ABI v3).
   - Candidate artifacts are opened exclusively through pinned directory file descriptors via `openat2(2)` with `RESOLVE_BENEATH | RESOLVE_NO_SYMLINKS | RESOLVE_NO_XDEV`.
   - Symlinks, hard-link escapes, mount-point crossings, and non-regular files are rejected fail-closed before any byte read.
3. **TOCTOU Race Prevention**:
   - Before hashing, the sensor verifies mount identity and link count via `fstat` and `statx(STATX_MNT_ID)`.
   - After hashing, inode, mount ID, size, and mutation timestamps are re-checked. Any discrepancy causes the digest to be immediately discarded with reason code `toctou_mutation_detected`.
4. **Network Egress Proxy**:
   - Outbound connections must traverse the nono network broker.
   - Connections to unapproved destinations are actively blocked and recorded on the timeline as `DENIED` evidence.

## Step-by-Step Onboarding Walkthrough

### 1. Register the Agent & Issue Enrollment Token

An attributable human operator logs in to Signal Loom and registers the external agent for their tenant:

```bash
curl -sS -X POST "https://dashboard.osramp.acme.local/api/v1/external-agents/register" \
  -H "Authorization: Bearer ${OPERATOR_OIDC_TOKEN}" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "agentmaxxing-researcher-01",
    "description": "AgentMaxxing autonomous code researcher running on external Linux host",
    "model": "anthropic/claude-3-7-sonnet",
    "framework": "nono-sandboxed"
  }'
```

**Response (`201 Created`):**
```json
{
  "agent_id": "agent-amxo-uuid-001",
  "tenant_id": "tenant-agentmaxxing",
  "enrollment_token": "amxo_enroll_sec_98f43b12390abcf",
  "expires_at": "2026-09-14T12:00:00Z"
}
```

The enrollment token is atomic, single-use, and valid for 24 hours.

### 2. Enroll the External Linux Host

On the target Linux host, the sensor agent redeems the one-time enrollment token to obtain audit-scoped credentials:

```bash
curl -sS -X POST "https://dashboard.osramp.acme.local/api/v1/external-agents/enroll" \
  -H "Content-Type: application/json" \
  -d '{
    "enrollment_token": "amxo_enroll_sec_98f43b12390abcf",
    "host_id": "linux-host-amxo-prod-42",
    "landlock_abi": 3,
    "kernel_version": "6.8.0-45-generic"
  }'
```

**Response (`200 OK`):**
```json
{
  "agent_id": "agent-amxo-uuid-001",
  "tenant_id": "tenant-agentmaxxing",
  "host_id": "linux-host-amxo-prod-42",
  "access_token": "amxo_audit_scoped_jwt_token_...",
  "spiffe_id": "spiffe://signalloom.demo/ns/agentmaxxing/sa/researcher-01",
  "audit_endpoint": "/api/audit/sessions"
}
```

These credentials have **least-privilege audit scope**: they can only upload audit sessions for `agent-amxo-uuid-001` and cannot query other tenant records or mutate platform state.

### 3. Configure the nono Sandbox Profile & systemd Service

Install the nono sandbox profile at `/etc/nono/profiles/agentmaxxing.yaml`:

```yaml
version: "0.73.0"
profile: "agentmaxxing-hardened"
landlock:
  abi: 3
  read_only:
    - "/usr"
    - "/lib"
    - "/etc/ssl/certs"
  read_write:
    - "/home/agent/workspace"
  deny:
    - "/etc/shadow"
    - "/home/agent/.ssh"
network:
  proxy_mode: "enforce"
  allow_destinations:
    - "api.anthropic.com:443"
    - "api.openai.com:443"
    - "dashboard.osramp.acme.local:443"
audit:
  enabled: true
  hash_chain: true
  integrity_marker: true
```

Configure the systemd service at `/etc/systemd/system/agentmaxxing.service`:

```ini
[Unit]
Description=AgentMaxxing Governed External Linux Agent
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=agent
Group=agent
WorkingDirectory=/home/agent/workspace
ExecStart=/usr/bin/nono run --profile /etc/nono/profiles/agentmaxxing.yaml -- /usr/local/bin/agent-runner
Restart=on-failure
RestartSec=5s
Environment="SIGNAL_LOOM_TOKEN=amxo_audit_scoped_jwt_token_..."
Environment="SIGNAL_LOOM_ENDPOINT=https://dashboard.osramp.acme.local"

[Install]
WantedBy=multi-user.target
```

Reload and start the service:

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now agentmaxxing.service
```

### 4. Ingestion, Verification, and Deduplication

As the agent executes, nono and the host sensor generate hash-chained audit events. When a session finalizes, the sensor submits the signed session to Signal Loom:

```bash
curl -sS -X POST "https://dashboard.osramp.acme.local/api/audit/sessions" \
  -H "Authorization: Bearer ${SIGNAL_LOOM_TOKEN}" \
  -H "Content-Type: application/json" \
  -d @/var/log/nono/finalized-session-001.json
```

The ingestion pipeline performs server-side verification:
- **Contiguous Sequence Checks**: Validates that all sequence numbers `1..N` form an unbroken chain.
- **Cryptographic Hash Chain**: Recomputes SHA-256 digests across preceding events; any tampered or forged record is rejected.
- **Upload Idempotency**: Duplicate submissions of identical sessions return `200 OK` without duplicating database state. Conflicting submissions under the same session ID return `409 Conflict`.
- **Finalization Markers**: Emits a terminal finalization event (`POST /api/audit/sessions/finalized`).

### 5. Inspecting Evidence on the Agent Timeline

Navigate to the Signal Loom Dossier for the agent (`/agents/{agent_id}?tab=activity`).

The **Activity Timeline** renders external evidence items with full cryptographic attribution:

- **Verification Badges**:
  - `INTEGRITY VERIFIED` (Green border & tag): The nono audit hash chain has been cryptographically validated server-side.
  - `TAMPERED HASH CHAIN` (Red border & tag): A sequence or digest mismatch was detected.
  - `UNVERIFIED` / `UNOBSERVED` (Amber border & tag): Expected telemetry was skipped, rate-limited, or unobserved.
- **Attributable Metadata**:
  - Process lifecycle: health status, CPU usage, RSS memory, exit code.
  - Artifact digests: verified workspace root, truncated SHA-256 hash, byte size, modification timestamp.
  - Network egress: destination IP/port and broker decision (`allowed` vs `blocked`).
  - Limits & Quarantines: reason codes (`RATE_LIMIT_EXCEEDED`, `toctou_mutation_detected`, `path_escape_attempted`).
- **Allowlisted Attributes Viewer**: Click **View Allowlisted Attributes** to inspect the sanitized JSON payload.

### 6. Host Revocation & De-Provisioning

When an external host is decommissioned or compromised, the operator revokes the host registration:

```bash
curl -sS -X POST "https://dashboard.osramp.acme.local/api/v1/external-agents/registrations/agent-amxo-uuid-001/revoke" \
  -H "Authorization: Bearer ${OPERATOR_OIDC_TOKEN}" \
  -H "Content-Type: application/json" \
  -d '{ "reason": "Host decommissioned" }'
```

Revocation takes effect immediately: subsequent audit upload attempts from the host are rejected with `403 Forbidden`, and a `revocation` audit event is published to the agent timeline.
