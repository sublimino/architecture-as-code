# AGENTS.md — osramp-demo

Canonical agent onboarding doc. Read this first, then the per-slice AGENTS.md
for whichever D2 installation you're working on.

## Repository Purpose

Monorepo for the OSRAMP / Signal Loom demo platform. Hosts multiple independent
D2 delivery slices sharing a common Kind cluster foundation, Flux GitOps
control plane, and Envoy Ingress Gateway.

## Shared Foundation Stack

| Layer | Technology | Location |
|-------|-----------|----------|
| Cluster | Kind (single-node `osramp`) | `make up` / `make cluster` |
| GitOps | Flux Operator + ResourceSets | `d2-osramp-fleet/` |
| Ingress | Envoy Gateway (Gateway API, TLS) | `d2-infra/components/ingress/` |
| Registry | Zot (in-cluster, persistent `.cache/zot`) | `d2-infra/components/registry/` |
| Signing | cosign + witness | `.keys/` (generated by `make signing-keys`) |
| Monitoring | kube-prometheus-stack + Grafana | `d2-infra/components/monitoring/` |
| Certs | cert-manager (self-signed cluster issuer) | `d2-infra/components/cert-manager/` |

## D2 Slices

Each slice is an independent deployment boundary. They share the cluster but
own their own namespaces, images, tests, and lifecycle.

## Quick Start

```bash
# 1. Foundation: Kind cluster + Zot registry + signing keys + Flux
make up

# 2. Pick a demo slice (or combine them):
make demo-signalloom-up    # Signal Loom
make demo-osramp-up        # OSRAMP apps
make demo-k8s-afm-up       # KubeSec-AFM
make demo-olly-up           # Olly Sentinel
make demo-bao-up            # OpenBao/SPIRE only

# 3. Health check
make healthcheck            # foundation readiness
make doctor                 # full configured-cluster state report
```

## Shared Lifecycle Commands

| Command | What it does |
|---------|-------------|
| `make up` | Foundation: Kind + Zot + signing keys + Flux |
| `make down` | Delete Kind cluster (Zot cache persists) |
| `make teardown` | Full reset incl. keys and build state |
| `make teardown-all` | Full reset incl. tools installed by setup.sh |
| `make healthcheck` | Verify foundation readiness for demos |
| `make doctor` | Alias for the comprehensive cluster diagnostic report |
| `make cluster-debug` | Comprehensive cluster diagnostic report (same as `make doctor`) |
| `make help` | List all targets |

## Shared Cluster Diagnostics

Run `make doctor` before investigating a cluster problem. `make doctor` and
`make cluster-debug` are equivalent, read-only entry points to the
comprehensive diagnostic report. It inspects cluster connectivity, unhealthy
pods, restart counts, warning events, Flux state, node metrics, and image-pull
failures. The detailed command-by-command runbook is in
[`TESTING.md`](TESTING.md#shared-cluster-diagnostics).

### Per-Slice Lifecycle Pattern

Every slice follows the same pattern:
```bash
make demo-<slice>-up        # Deploy
make demo-<slice>-test      # Static + readiness checks
make demo-<slice>-down      # Remove (keeps foundation)
```

## Pitfalls (Shared)

### Port-forward dies on pod rollout
Every `kubectl rollout restart` kills active port-forwards. Restart them after
any image rebuild + deploy cycle.

### Mutable `:latest` tag with `imagePullPolicy: IfNotPresent`
After `kind load docker-image`, verify the pod picked up the new image:
```bash
kubectl get pod <name> -n <ns> -o jsonpath='{.status.containerStatuses[0].imageID}'
```
If stale, `kubectl delete pod <name>` forces re-resolve.

### Worktree location
Worktrees go in `~/src/.worktrees/<repo>/<branch>/`, never inside the repo.
In-repo `worktrees/` directories bleed into bun/find/rg/test-runners.

### Zot cache persistence
`.cache/zot/` survives `make down` (intentional — avoids re-pulling). Use
`make zot-cache-reset` to clear it.

## Conventions

- **Commits**: conventional commits with slice scope — `feat(signalloom):`, `fix(osramp):`, `test(k8s-afm):`
- **Signing**: all commits GPG-signed; all images cosign-signed
- **Supply chain**: SBOM (SPDX), SLSA provenance, digest verification
- **Everything signed**: nothing deploys unsigned, even locally
- **Tests ship with code**: new features include unit + integration + acceptance coverage
